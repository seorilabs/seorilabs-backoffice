# 달빛 맞고의 신규 설치 흐름과 재방문 조회

사용자가 승인한 달빛 맞고 1.1.0 계획의 Backoffice 조회 연결을 구현한다. 실제 데이터셋과 원시 행, 공용 조회 identity 접근을 확인하기 전에는 운영 연결을 활성화하지 않는다. 이 구현은 기존 중앙 활성 연결을 읽고 집계만 조회한다. DB 설정과 수집 대상을 직접 만들거나 바꾸지 않는다.

`GET /api/admin/analytics/matgo-cohorts?days=7` 또는 `days=14`는 기존 관리자 토큰으로 보호한다. 첫 실행에서 분석을 허용한 새 저장만 분모에 넣고 기존 저장 이전, 나중 참여와 SDK 초기화는 제외한다. 사용자 단위로 테스트와 SDK debug 표식도 제외한다. 최초 대국 시작 뒤 정상 완료, 정상 완료 뒤 두 번째 시작의 순서를 검사한다. 코호트 기준일은 최초의 유효한 `analytics_ready` 보고 날짜다. SDK 접속 시각이 허용보다 앞서도 그 시각을 대신 쓰지 않는다. 두 번째 시작률은 시작과 완료가 순서대로 확인된 첫 판 완료자만 분모에 넣는다. D1과 D7은 실제 일별 테이블이 있는 관찰일만 계산한다. 누락일과 미성숙 지표는 0으로 채우지 않는다.

기존 범용 `first_open` 재방문 지표는 바꾸지 않는다. 달빛 맞고의 `analytics_ready`와 `install_cohort` 계약을 사용하는 별도 운영 조회다. SQL은 달빛 맞고 `analytics/cohorts.sql`의 계약을 유지한다. 조회 엔진의 기존 위치 탐지, 과금 상한과 실행 기록을 재사용한다. 날짜와 식별자는 SQL 조립 전에 검사한다. 수치 응답이 잘못됐으면 0으로 바꾸지 않고 조회 실패로 반환한다.

새 화면은 없으므로 시각 개편과 기기 검수는 해당하지 않는다. 날짜별 내보내기 누락, 코호트 없음, 테스트 제외, 순서 검사와 null 보존을 개발 환경에서 검사하고 typecheck, lint, build를 수행한다. 실제 GA4 수신, BigQuery 행과 API 운영 조회는 별도 미완료 항목으로 남긴다. 코드는 되돌릴 수 있는 단일 조회 추가이며 기존 수집과 보고서를 변경하지 않는다.

승인 근거는 현재 대화의 「달빛 맞고 분석 기반 개선과 양마켓 공개 계획」 구현 지시와 `seorilabs/matgo#65`다. 이 조회는 분석 연결과 운영 기록 범위다.
