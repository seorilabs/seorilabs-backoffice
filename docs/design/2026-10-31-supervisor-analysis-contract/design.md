# 대표 분석의 도구 이름 계약 복구

## 문제와 근거

승인받은 대표 에이전트 운영 연결 중 첫 자연 분석은 2026-10-31T03:29:39Z에 두 후보를 만들었다. 첫 후보의 설계와 테스트 계획은 `2425dfe9b84d08934d11c87176cd963f47dd2b74`에 고정됐지만 서버 등록 전에 거부됐다. CLI 출력 JSON Schema는 도구를 임의 문자열로 허용하고 서버 proposalSchema는 고정된 아홉 식별자만 받는다. 실제 `Git`, `GitHub API`, `Godot`, `npm`, `MiniMax Code`는 서버의 허용값이 아니다.

## 수정 범위와 흐름

PC의 analysis.schema.json에서 tools의 항목을 기존 서버 enum과 같게 제한한다. 분석, 설계 커밋, 기존 서버의 검증, 사람 승인, 실행 순서를 유지한다. 서버의 허용값과 권한, 데이터, 화면, 실행기는 바꾸지 않는다. 잘못된 입력을 서버가 거부하는 동작도 유지한다. 별칭 변환이나 서버 검증 완화는 추가하지 않는다.

서버와 웹은 UI12~14와 L3를 통과해 이미 배포한 `9bc5a4a` 이미지로 운영한다. 이번 산출물은 PC에 설치하는 JSON Schema이며 서버 이미지를 다시 배포하지 않는다. 설치 파일의 정본은 병합한 Git 커밋과 설치 영수증이다.

## 검증과 완료 조건

서버 enum과 CLI 출력 enum이 같고, 실제 실패한 표기가 CLI schema 단계에서 거부되는 회귀 검사를 먼저 실행한다. 수정 뒤 같은 검사가 통과해야 한다. 기존 TypeScript, Python 실행기 전체 검사와 저장소의 타입, lint, 빌드 및 필수 CI를 통과한다. 다른 실행자가 PC 설치 파일과 기존 서버에 대한 실제 제안 등록을 읽어 확인한다. 기존 서버의 UI12~14, 서비스 회귀와 중앙 네 gate는 원래 SHA에 그대로 보존하며 새 PC 커밋의 화면 실행으로 소급하지 않는다. 추가 UI 회차는 실행하지 않는다.

첫 자연 후보의 문제와 근거, 범위와 설계는 보존한다. 복구 시 도구 표기만 기존 식별자로 정리하고 검토본이 아직 없음을 읽은 뒤 등록한다. 이 작업은 승인이 아니며, 정확한 버전의 사람 승인 없이 실행하지 않는다.

## 승인과 운영

기존 사용자가 승인한 대표 에이전트 구축, PC 실행기 설치와 최초 자연 관측 연결 범위에서 발견한 구현 오류를 고친다. 관찰 모드와 승인 경계의 의미는 바꾸지 않는다. 신규 관측과 claim은 로컬 실행기를 정상 중단해 멈췄고 승인, 실행 이력은 보존했다. 검증한 PC 산출물을 설치하고 정상 재기동한다. 오류가 남으면 실행기를 중단한 채 정확한 상태를 보고한다.
