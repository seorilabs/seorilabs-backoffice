# 건별 알림과 리뷰 일간 통계

사용자 지시와 선택에 따라 리뷰, 광고 보상, 결제를 건별로 발송하고, 전날 리뷰 통계를 매일 11시 KST에 보낸다. 신규 계정은 `[게임명:버전] 신규계정#번호 - 나머지 정보`로 표시하고 운영 조회용 Platform 사용자 ID를 추가한다. L1 개발 환경 서비스 검증, PR과 운영 반영 범위다. 이 문서가 승인 범위를 고정하며 플랫폼 생산자의 추가 계약은 별도 Platform PR과 연결한다.

```text
스토어 수집 → 새 리뷰 또는 수정 리뷰 → 건별 즉시 발송
전날 수집된 리뷰 → 앱과 마켓별 통계 → 매일 11시 KST 발송
Platform 확정 지급 → 광고 보상 또는 결제 건별 발송
Platform 계정 생성 → 일별 번호와 버전, 운영 UID → 앱운영이벤트
```

예시(합성값): `**[도마뱀 테라리움:1.8.4]** 신규계정#1 - firebase / anonymous / Android / 10:05 / UID: pu_01ARZ3NDEKTSV4RRFFQ69G5FAV`.

## 결정과 경계

- 리뷰 수집의 기존 30분 주기와 최초 기준선은 유지한다. 수집된 신규 및 수정 리뷰는 15분 분석을 기다리지 않고 기존 user-reviews 목적지로 보낸다. 기존 15분 주제 분석의 Discord 보고는 일간 통계로 대체하고 내부 근거는 보존한다.
- 통계는 전날 00:00~24:00 KST에 수집한 리뷰 관측을 앱과 마켓별로 묶는다. 같은 리뷰의 여러 수정은 마지막 별점 한 개로 집계하며 해당 날짜에 신규 관측이 있으면 신규, 아니면 수정으로 분류한다. 평균과 1~5점 분포는 같은 중복 제거 표본을 쓴다. 스토어 전체 누적 평점이라고 표시하지 않는다. 자료가 없으면 빈 보고는 보내지 않는다.
- 기존 인사이트 worker의 1분 실행에서 11시 이후 전날 통계를 생성한다. 같은 날짜와 앱과 마켓 키로 같은 카드만 갱신하며 재시작, 재실행과 늦게 저장된 자료에도 추가 메시지를 만들지 않는다. 건별 발송과 통계의 발송 상태는 독립이다.
- 결제는 실제, 테스트, 제공 안됨을 표시한 건별 카드로 보낸다. 광고 보상 성공도 매건 전용 채널로 보낸다. 실패는 기존 장애 카드를 사용하며 알려진 테스트 결제 실패도 결제 채널에 사실로 표시한다. 다른 주문 성공으로 장애를 해결 처리하지 않는다. 첫 지급 성과와 동일 건의 중복 카드는 만들지 않는다.
- 계정 번호는 앱별 KST 일별 원장 순서를 사용한다. 동일 이벤트 재시도는 기존 발송 키와 번호를 유지한다. 앱 버전이 없으면 제공 안됨으로 표시한다. 신규 계정의 최초 축하 카드는 건별 한 줄에 통합하여 한 이벤트가 두 번 오지 않게 한다.
- `platformUserId`는 신규 계정 속성에만 선택적으로 허용한다. 서버가 생성한 `pu_`와 26자리 ULID 형식만 받고 앱 로그인 UID, 이메일, 토큰과 결제 식별자는 계속 거부한다. UID가 없는 과거 이벤트는 값을 추정하지 않는다. Backoffice 수신자를 먼저 배포하고 Platform 생산자를 다음에 배포한다. 기존 원장, 알림 키와 schema는 유지한다.

## 인수조건과 검증

AC-1 리뷰의 신규와 수정은 개별 전송되며 최초 기준선과 중복 방지가 유지된다. AC-2 일간 통계는 11시 경계, KST 날짜, 같은 리뷰의 마지막 별점, 시장 구분, 빈 표본과 재실행을 검증한다. AC-3 광고와 결제는 전용 채널로 모든 건을 보내고 주문 환경을 사실대로 표시하며 장애 경로를 보존한다. AC-4 새 계정 형식, 일별 번호, 버전과 선택 UID, 재전송을 실제 수신 라우트로 검증한다. AC-5 잘못된 UID와 사용자 정보 속성을 거부하고 서명 및 보고 중지를 유지한다.

L1, dev/service-runtime. 격리 저장 경계와 실제 수집, POST, outbox, 통계 서비스로 요구사항 실패 후 통과를 확인한다. 관련 회귀, typecheck, lint, build를 실행하고 실제 Discord 본문과 상태를 별도로 확인한다. 새 화면이나 탐색 구조를 만들지 않는 기존 메시지 표시와 서비스 변경이며 기기를 쓰지 않는다. 개인정보와 알림 중복 경계는 로컬 Claude 교차 리뷰를 받는다.

## 운영과 복구

Ready PR, CI와 중앙 검증 후 immutable 이미지로 웹, 알림 worker, 인사이트 worker와 리뷰 CronJob을 범위에 맞게 갱신한다. replicas, 주기와 Secret은 보존한다. migration 검증과 이후 provider audit 관측을 먼저 확인한다. 전체 reconcile 실패 #517은 이번 범위와 구분한다. 실제 새 자료 또는 명시한 최근 미발송 실제 한 건씩으로 발송을 확인하며 과거 메시지 전체를 자동 재발송하지 않는다. 실패하면 영향 컴포넌트의 이전 이미지를 복구할 수 있으며 기존 원장과 메시지를 삭제하지 않는다. Version Impact: patch.
