## 구조와 실패 처리

1. `src/lib/book-sales/notification.ts`의 목적지를 기존 `app-ops`로 변경한다. 기존에 발송한 메시지를 삭제하거나 과거 판매 변경을 일괄 재발송하지 않는다.
2. `src/lib/market/keyword-collector.ts`, `cycle-report.ts`, `scripts/operations-insights-worker.ts`에서 수집 중단을 재현하고 수정한다. 수집 회차·계획·개별 관측을 보존하고 재시도는 저장된 관측을 덮어쓰지 않는다. 카테고리 수집과 보고가 키워드 수집·선별 결과에 종속돼 빠지는 경로를 분리한다. 정상 완료, 부분 완료, 실행 실패를 명시적으로 반환하고 보고 Job이 조용히 성공 처리하지 않게 한다.
3. GA4 `collectMetrics`, 앱인토스 예약 수집, 수동 `ingestAndVerifyConsolePush`가 공통 완료 서비스를 사용한다. 수집 실행 ID, 출처·기준 기간·성공 범위, 고정한 근거 묶음과 분석 요청을 결속한다. 수집 저장 뒤 분석 요청이 유실되는 간극은 같은 트랜잭션 또는 완료 원장 기반 재조정으로 복구한다. 완전 실패도 새 자료가 없다는 결과를 남기며 과거 수치를 이번 수집 결과로 표시하지 않는다.
4. 기존 `OperationalSignal`, `InsightDocument`, `AutomationOccurrence`, `AgentRun` 분석 대기열과 알림 outbox를 재사용한다. 외부 AI 호출은 수집 API 응답과 DB 트랜잭션 밖에서 실행한다. 현재 operations-insights worker는 `replicas=0`, 기존 PENDING 문서는 12건이다. 새 수집 분석 종류만 처리하도록 필터를 추가하고 필요한 worker를 활성화한다. 예전 12건과 다른 신호를 한꺼번에 재발송하지 않는다.
5. 같은 수집 실행 ID의 재시도는 같은 분석 요청과 Slack 메시지를 사용한다. 서로 다른 수집 실행이면 수치가 같아도 이번 실행의 결론을 보고한다. AI 실패는 제한된 재시도 후 사실 기반 보고로 끝내고 원장에 실패를 남긴다. Slack 전송의 결과 불명과 권한 실패는 기존 outbox 규칙을 유지한다.
6. 일일 정정 경로는 새 사실 묶음으로 해설을 다시 만들고, 게시 직전 사실 지문과 버전을 대조한다. 생성 중 다른 정정이 먼저 반영되면 오래된 해설을 붙이지 않는다. 오전 정시 발행의 원본 입력 고정과 보고서 버전 이력은 유지한다.

새 DB schema와 별도 운영 JSON 정본은 만들지 않는다. 중앙 설정, 수집 대상 국가·검색어·리스팅, 수집 간격과 공급자별 요청 제한, LLM 모델·예산은 유지한다. 원인이 자원·요청 제한과 관련 있으면 무조건 한도를 늘리지 않고 기존 예산 안에서 재개와 실패 격리를 먼저 적용한다. 추가 자원·유료 한도·권한 변경이 필수면 그 근거를 별도로 확인한다.

## 주요 결정

- 순위 채널은 기존 ID를 유지하며 이름만 변경했다. 새 채널을 만들어 구독과 이력을 나누지 않는다. 내부 `metrics-daily` 이름을 바꾸는 이관도 필요하지 않다.
- KDP와 수집 인사이트는 기존 재무·지표 보고 채널을 사용한다. 이번 요청에 없는 새 보고 채널은 만들지 않는다.
- 지표 보고는 수집 완료를 기준으로 한다. 시간표에 일일 분석 하나를 추가하는 방법은 늦은 수집과 수동 push의 분석을 보장하지 못해 채택하지 않는다.
- 매 수집 뒤 보고한다는 이번 요청에 따라, 변화가 없더라도 결과를 짧게 전달한다. 표본이 부족할 때 원인이나 행동을 억지로 생성하지 않는다.
- 화면 구조를 바꾸는 작업은 아니다. 기존 카드 형식과 근거 링크를 사용하므로 UI 재설계 검수는 해당하지 않는다.

## 적용과 복구

승인 범위 제안은 구현, L1 검증, Ready PR과 필수 검사·병합, 서비스 배포, 현재 순위 회차 복구 1건과 각 보고의 Slack 수신 확인까지다. [테스트 계획](test-plan.json)의 `service/public`은 이 운영 적용 범위를 나타내며 앱 마켓 출시와 관계없다. 배포 전 중앙 검증을 실행하고 확인된 기존 이미지와 설정을 복구 대상으로 남긴다.

이상 시 새 분석 종류의 처리를 중단하고 기존 이미지·worker 실행 수로 복원한다. 수집·분석·발송 이력은 보존한다. 이미 보낸 메시지를 삭제하지 않으며 오류 보고가 있으면 해당 메시지의 정정 경로를 사용한다. 자연 예약 실행을 관측하기 전에는 복구 실행만 확인한 것으로 보고한다.

실행 중 자료는 NAS1dual에 크기·해시 대조 후 보관하고 Git에는 텍스트 요약과 위치만 남긴다. 이번 조사에서는 원본 다운로드나 대용량 증적 파일을 만들지 않았다. 승인 뒤 실행 이슈와 승인 커밋, PR, 검수·배포 결과를 이 문서에 연결한다.
