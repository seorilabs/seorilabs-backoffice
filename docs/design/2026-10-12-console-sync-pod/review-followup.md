# 인증·재시도 경계 보완 재검토

- 원 설계: [승인 v1](design.md), 실행 PR: [#462](https://github.com/seorilabs/seorilabs-backoffice/pull/462).
- 상태: 구현·회귀 검증 후 사람의 설계 재검토 필요. 운영 배포·스케줄 활성화 승인은 포함하지 않는다.
- 사유: 2회차 교차 리뷰에서도 인증·재시도 영역의 실패 시나리오가 발견됐다. `seori-pr-workflow`의 2회 상한을 적용하고 추가 모델 리뷰를 요청하지 않는다.

| 보완 | 실행 동작 | 확인 근거 |
| --- | --- | --- |
| 429 남은 예산 | 요청 전체 25초 안에 Retry-After를 기다릴 수 없으면 대기/추가 조회 없이 RATE_LIMITED·부분 완료. | 실제 20초 Retry-After 연속 2회 HTTP 시험 |
| 갱신 결과 불명 | 공유 갱신이 취소·네트워크 실패하거나 성공 본문이 불완전하면 OUTCOME_UNKNOWN으로 현재 연결을 중단하고 옛 refresh를 재사용하지 않음. | 공유 대기자·취소·새 호출 거부 assertion |
| 비JSON 오류 | 4xx/5xx 본문을 읽지 못해도 HTTP 상태·안전한 설정 오류 구분을 유지. | 빈/HTML 오류와 불완전 2xx assertion |

공유 갱신에 전달한 요청 예산 때문에 다른 대기자도 실패할 수 있다. 결과가 불명확한 grant를 자동으로 다시 사용하는 것보다 현재 연결을 중단하는 보수적 선택이다. 원본 파일을 변경하거나 회전 토큰을 임의 보존하지 않는다.

중단 상태는 실행 프로세스 안에서 유지한다. 운영 중 재인증·회전·결과 불명 오류가 발생하면 운영자가 스케줄을 중지하고 기존 grant 상태를 확인한 뒤 사람의 재인증/보존 설계를 검토해야 한다. 다음 일일 Job까지 자동으로 막는 영속 credential 상태·자동 Secret 쓰기는 현재 설계 범위 밖이다.

일반 비밀 키 변형 차단, 중복 날짜의 모든 행 보류, 기존 명령 정본 연결도 반영했다. 지표 스키마·대상 목록·공통 overlap 정책·권한·모델 사용 범위는 원 설계를 유지한다. 실제 OAuth·파드 재시작·운영 readback과 전체 제품 E2E는 여전히 차단이다.
