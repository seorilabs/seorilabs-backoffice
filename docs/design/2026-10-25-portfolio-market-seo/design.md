# 앱 포트폴리오 마켓 검색 노출 점검과 1차 개선 설계 v1

점검일: 2026-10-25 KST. 기준 저장소: `e49e6e4e9f33698c52b978b845aa3e4335509dbc`. 설계 승인: 대기. 마켓 저장, 심사 제출, 공개 반영: 미실행.

## 결론

먼저 공개 중인 앱 5개의 검색 문구를 고치고, 현재 이름을 놓치는 검색어 관측을 보완한다. 1차 대상은 블룸핸드, 가로세로 퍼즐, 함께봄, 조물조물, 루시드 체스다. 현재 장르와 기능을 제목과 부제에 드러내며 상세 설명과 이미지의 변경은 2차로 분리한다. [변경 전후 문안](proposed-copy.md)에 실제 저장할 45개 필드를 적었다.

앱인토스의 기존 가로세로 퍼즐 웹 리스팅은 정책 위반으로 노출이 중단됐다. 별도 게임 리스팅의 현재 출시와 구분한다. Google Play 새 계정의 소유 앱 조회는 자동 로그인 차단으로 완료하지 못했으므로 전체 포트폴리오 점검 완료나 마켓 개선 반영 완료로 기록하지 않는다.

## 조사 범위와 자료의 한계

- Backoffice 등록 행 36개를 조회했다. 상태는 ACTIVE 27개, PAUSED 4개, DEPRECATED 5개다. 내부 플랫폼과 준비 중 앱도 포함되므로 36개가 공개 앱 수는 아니다.
- App Store Connect 25개 앱, AppInfo 현지화 레코드 69개를 조회했다. 같은 앱의 공개 AppInfo와 제출 준비 AppInfo가 함께 있으면 중복 언어 레코드도 세었다. 최신 두 버전의 키워드와 설명을 함께 읽었다.
- Apple 공개 lookup을 한국과 미국에서 각각 조회했다. 각 16개 결과를 받았다. 국가별 차이와 비공개 초안을 구분했다. 결과 목록에 없는 앱은 해당 국가 lookup 미확인으로 기록하며 전 세계 미출시로 단정하지 않는다.
- Google Play 공개 상세 페이지를 29개 패키지의 한국어 한국, 영어 미국 조합으로 58회 조회했다. 46회에서 제목, 짧은 설명, 상세 설명을 읽었다. 확인한 패키지는 24개다. 404는 해당 국가와 패키지 조합의 조회 결과다.
- Google Play Seolee Apps 개인 계정 5547060480954653351의 앱 목록 11개를 두 페이지에서 확인했다. 새 기본 계정은 provider_blocked라 소유 계정 ID와 전체 목록을 읽지 못했다. 공개 페이지의 개발자 이름만으로 계정 소유를 확정하지 않았다.
- 앱인토스 작업공간 38345의 19개 리스팅에서 등록 문구와 출시 화면을 조회했다. meta/edit 값은 저장된 편집값이며, 공개 중인 문구와 같다고 단정하지 않는다. 현재 출시됨 표시는 Console 상태이며 토스앱 실제 진입 성공과 구분한다.
- Backoffice의 2026-10-18부터 10-24까지 Apple 검색어 관측 777개를 읽었다. 최신 10-24 표본은 12개 앱, 111개 검색어와 국가 조합이며 이 중 43개는 응답 목록에 앱이 없었다. 실제 단말 App Store 검색 순위, 검색량, 설치 유입과 같은 값은 아니다.
- 1차 5개 앱의 한국과 미국 공개 첫 스크린샷 9장을 봤다. 전체 이미지, 앱 미리보기와 모든 언어 이미지 검수는 남아 있다. 검색량, 스토어 검색 유입, 노출 대비 설치 전환율은 이번에 확보하지 못했다. 유료 광고나 유료 분석 도구는 추가하지 않았다.

## 실행 순서와 승인 범위

1. 이 설계 v1과 36개 문안과 두 마켓의 45개 필드, 관측 검색어 추가를 한 번에 승인받는다. 사람 승인은 이 구체적 변경 목록에 결합한다. 준비 중이거나 중지된 앱, 새 마켓과 국가, 가격, 법적 선언, 바이너리 변경은 대상에서 제외한다.
2. 대상별 GitHub 기본 브랜치 SHA, 최신 discovery와 ACTIVE 설정, 기존 DRAFT와 심사 상태를 다시 읽는다. 기존 사용자 초안이 있으면 병합 방법을 확인하며 덮어쓰지 않는다.
3. 기존 control-plane API 또는 같은 서비스를 쓰는 인증된 서버 액션으로 새 DRAFT 설정 버전을 만든다. validator, 앱 범위 권한, revision 비교, 멱등성과 감사 기록을 유지한다. legacy JSON이나 직접 Prisma 쓰기로 대신하지 않는다.
4. 같은 API의 허용 범위에서 비민감 설정만 활성화한다. Google Play 소유 계정과 API 권한을 확인한 앱만 metadata를 저장하고 공식 GET 또는 Console로 45개 필드 원문을 대조한다. 저장과 검토 접수, 공개 반영은 각각 기록한다.
5. App Store는 기존 수정 가능한 다음 버전에 적용한다. 새 버전이 필요하면 앱별 다음 승인된 릴리스로 연결하고 임의 SemVer를 정하지 않는다. 제목 변경을 위해 공개 버전이나 심사 중 항목을 철회하지 않는다. 제출은 모든 활성 언어와 이미지 검수 후 승인된 앱별 릴리스 범위에서 수행한다.
6. 공개값 확인 시각을 기록한 뒤 관측을 시작한다. 승인된 범위 안의 저장, 재조회와 공개 확인을 단계마다 재승인받지 않는다. 범위를 벗어나는 버전, 계정과 정책 결정만 질문한다.

현재 실행 차단: Play 새 계정 자동 로그인 provider_blocked. 중앙 control-plane API의 ADMIN bearer가 운영 Web 환경에 미구성임을 확인했다. 기존 운영용 x-admin-token은 이 API의 대체 인증이 아니다. 인증된 UI 또는 등록된 제어면 identity가 확보될 때까지 DRAFT 저장도 미실행으로 둔다. 자격증명 생성이나 인증 경계 우회는 하지 않는다.

## 검증과 성과 측정

- L1, 개발 환경에서 문구의 길이, 중복 키워드, 실제 출시 기능, 대상 마켓과 locale을 확인한다. 저장 전후 원문 비교와 다른 언어 보존을 확인한다. 문구만 바꾸므로 기기 사용은 필요 없다. 제품 실행, SDK와 결제를 통과했다고 기록하지 않는다.
- Apple 30자 제목, 30자 부제, 100자 키워드, Play 30자 제목과 80자 짧은 설명을 검사한다. 상세 설명을 바꾸게 되면 각각 4,000자 한도와 모든 변경 문장을 추가 검수한다.
- 변경 전 14일, 공개 반영 후 14일을 같은 국가, 언어와 요일 구성으로 비교한다. 작은 표본은 28일까지 관찰하되 유의한 변화라고 단정하지 않는다. 이 기간은 관측 계획이며 예약 작업을 추가한 상태가 아니다.
- 공식 스토어에서 확보할 수 있는 검색 유입 노출, 방문과 최초 설치를 우선 지표로 쓴다. 현재 미확보 값은 null 또는 미확보로 유지한다. 검색어 API 순서는 보조 지표다. 검색어의 응답 목록 진입 여부와 결과 수를 함께 기록한다.
- 같은 기간에 아이콘, 스크린샷, 가격과 광고 지출을 함께 바꾸지 않는다. 바이너리 릴리스나 다른 변경이 겹치면 비교의 교란 요인으로 남긴다. 작은 포트폴리오에서 동시 실험으로 인과효과를 보장하지 않는다.
- 기능형 제목의 정합성과 정책 적합성은 필수 인수조건이다. 순위나 설치 상승은 검증할 가설이며 보장하는 인수조건으로 두지 않는다. 반영 후 혼동이나 검색 유입 하락이 확인되면 이전 문안을 새 설정 revision으로 복구한다.

## 2차 이미지와 포트폴리오 보완

- 함께봄 첫 스크린샷은 일반 기록 홈을 보여준다. 공동 기록이라는 차이가 보이는 실제 초대 또는 공동 타임라인 이미지를 우선 후보로 삼는다. 개인정보는 격리된 개발 데이터만 쓴다.
- 조물조물 첫 스크린샷은 재료와 도감 중심이다. 두 재료, 합치기, 새 발견의 실제 화면을 이어 보여주는 후보를 준비한다. 콘텐츠 수와 기능은 해당 마켓의 현재 버전 기준으로 검수한다.
- 루시드 체스는 실제 보드가 보이지만 후보 수와 복기 가치를 설명하는 이미지가 첫 슬롯에 필요한지 전환 데이터를 보고 판단한다. 블룸핸드의 첫 이미지는 이미 카드 조합과 꽃이라는 가치를 설명한다.
- 중지 앱 4개와 폐기 앱 5개는 목록과 공개 상태만 점검했다. 복구, 리브랜딩이나 신규 마켓을 이번 SEO 작업으로 재승인하지 않는다. 새로 발견한 앱의 제품 등록과 계정 소유 정리는 별도 운영 계획으로 연결한다.

- [Apple 검색 안내](https://developer.apple.com/app-store/search/): 제목, 부제와 키워드의 관련성 및 사용자 행동을 검색 요소로 설명한다.
- [Apple 상품 페이지](https://developer.apple.com/app-store/product-page/): 부제와 키워드 한도, 중복과 경쟁 앱 이름 배제, 홍보 문구의 검색 순위 비영향을 따른다.
- [Google Play 등록 규격](https://support.google.com/googleplay/android-developer/answer/9859152?hl=en): 제목 30자, 짧은 설명 80자, 상세 설명 4,000자.
- [Google 메타데이터 정책](https://support.google.com/googleplay/android-developer/answer/9898842?hl=en), [등록 권장사항](https://support.google.com/googleplay/android-developer/answer/13393723?hl=en): 기능과 일치하는 문구, 무관한 검색어 반복과 순위 과장 배제.
- [앱인토스 주요 기능 등록](https://developers-apps-in-toss.toss.im/guide/operation/function.md): 비게임 앱의 실제 기능별 진입은 최대 3개. 실제 딥링크가 확인된 뒤 별도 제안하며 게임에 일괄 적용하지 않는다.
