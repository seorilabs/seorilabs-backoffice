# 실행 기록

접수 이슈: [#554](https://github.com/seorilabs/seorilabs-backoffice/issues/554). 승인된 하루 3회 보고 계약의 결함 수정이며 새로운 발송 조건이나 일정은 추가하지 않는다.

- 운영 읽기 전용 진단: 현재 411행, 과거 회차 1,233행과 일별 2,624행. SQL 조회는 합계 1초 미만, 전체 계산은 약 64초. 모든 쓰기를 차단한 진단이며 알림은 전송하지 않았다.
- 원래 코드의 격리 MySQL 9.2 실행: 1초 트랜잭션 예산에서 7,101ms 뒤 P2028 만료. 운영의 30초 예산과 개발 환경 압축 예산은 구분한다.
- 수정 후 같은 자료와 예산: 생성과 같은 회차 재실행 합계 423ms, Slack delivery 1개. 원래 30초 예산의 수정 전 정상 실행과 비교해 보고 payload 전체가 같다. 411행, 선택 3개와 28일 점, 순서와 표시를 보존했다.
- 별도 격리 DB에서 기존 세 회차, 재시도 불변, 마지막 성공 유지, 마켓 분리, 보고 중복 방지, 일별 조회 실행이 통과했다.
- 실제 worker CLI의 keyword-daily 모드 실행을 확인했다. 외부 provider는 호출하지 않았고 운영 설정 및 운영 관측은 수정하지 않았다.

타입 검사, lint, 전체 테스트, 웹과 worker 빌드, 로컬 코드 리뷰 및 최종 후보의 중앙 검증 결과는 후보 SHA를 바꾸지 않도록 source 밖의 evidence에 고정한다. 빌드와 배포, 실패 회차 복구, Slack 확인은 별개다.

증거 원본은 `/Volumes/Data/Backup/agent-artifacts/seorilabs-backoffice/2026-10-30/keyword-report-recovery-554/`에 복사한 뒤 직접 읽기의 크기와 SHA-256을 검증한다. 최종 검증 JSON과 실제 운영 결과는 해당 manifest와 GitHub 검증 기록에 연결한다. 현재 문서만으로 아직 실행하지 않은 배포나 Slack 수신을 통과 처리하지 않는다.
