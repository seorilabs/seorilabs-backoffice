# 통합 지표 수집·오전 11시 보고·개선 이슈 자동화

승인 근거: 2026-10-18 사용자가 제공한 같은 제목의 계획을 구현·검증·운영 공개까지 실행하라는 요청. 이 문서는 그 범위의 저장소 정본이며 승인 범위를 축소하지 않는다.

## 목적과 흐름

공식 자료 → 수집 원장과 출처 검증 → 10:45 KST 입력 고정 → 계산과 그림 준비 → 11:00 KST 웹·Discord 발행 → 늦은 자료는 새 버전과 기존 카드 정정 → 중앙 02시·14시 등록 작업에서 근거 있는 개선 이슈 연결.

첫 화면은 오늘의 결론(최대 3개), 하이라이트·로우라이트, 발견→설치→첫 핵심 행동→재방문→수익의 실제 연결 가능한 흐름, 앱 비교, 다음 행동, 데이터 상태 순서다. 발행 상태·수집 상태·수치 상태를 분리한다. 자료 지연이나 해설·이미지 실패로 정기 발행을 생략하지 않는다.

## 구조와 데이터

- 기존 GA4·앱인토스 스냅샷, MetricCollectionLedger, SourceCollectionRun, OperationalSignal, InsightDocument, OrgReportDaily/Revision, notification outbox와 중앙 설정·실행 대기열을 확장한다.
- 운영 대상 전체를 보고하며 이슈 대상은 최신 중앙 정책으로 별도 판단한다. 앱×계정×소스×보고서별 실제 권한·자료·SDK·내보내기를 조사한다. 즉시 연결·권한/입력 필요·계측 필요·비대상을 구분한다. 조사 전 추정 연결은 만들지 않는다.
- Google Play·App Store·GA4·Firebase 품질·AdMob·앱인토스·운영/고객/시장·비용·집행 계정·실제 실험/메시지를 조사한다. 공식 API 우선, 공식 파일은 출처·해시·중복 검증을 거친다. 새 유료 계약·키는 만들지 않고 입력 과제로 남긴다.
- 지표 사전은 정의·단위·분모·합산·개선 방향·차원·지연을 보존한다. 관측에는 기간·시간대·통화·대상·실행·원천 해시를 결속한다. 중앙 설정은 기존 validator·RBAC·동시성·감사 서비스를 통한다.
- 정상 관측·확인된 0·미도착·일부 수집·권한 필요·계측 필요·실패·비대상을 구분한다. 테이블 부재와 경과일은 0의 근거가 아니다. 비율은 분자/분모로 재계산한다. 날짜·시간대·통화·대상이 다른 합계와 증감, 중복 광고 수익, 근거 없는 비용 배분을 금지한다.
- 제공되는 최근 90일 초기 수집과 변경 원천·미확정 기간 증분 처리를 지원한다. D30 코호트를 재계산하며 기존 조회 비용 상한과 보존 정책을 유지한다.
- 발행 문서에 컷오프·대상/설정·소스 기준일·계산 근거·그래프·인사이트/이슈 상태를 고정한다. 과거 문서를 계속 읽고 같은 버전의 웹·Discord·CSV가 동일 자료를 사용한다. 정정 전 원본을 보존한다.

## 실패와 운영

발행 전 외부 수집·해설·그림을 마치며 발행 작업은 저장된 자료만 읽는다. 실패하면 검증 수치·고정 문장·웹 링크로 발행한다. 발행과 전송 실패는 분리한다. Discord는 기존 메시지 편집과 outbox 재시도로 중복을 막고 첨부·링크·수치·공유 범위를 확인한다. 월요일 주간 추세와 월간 정산 자료도 같은 보고에 연결한다.

새 소스·자동 등록은 각각 중지 가능해야 한다. 기존 자료와 과거 보고서를 보존하고 대체 검증 전 중복 경로를 지우지 않는다. 운영 적용은 exact SHA·digest와 웹·worker·CronJob별 readback으로 판정한다.

## 변화 판단과 이슈

직전 7일 중앙값에 유효 4일 이상, 가능하면 최근 4주 같은 요일을 비교한다. 기존 임계는 유지한다. 새 수량은 30%와 5건, 비율은 분모 50과 5%p, 금액은 같은 통화 30% 변화가 2개 분석 가능 기간 연속일 때 후보이며 금액 변화만으로 이슈를 만들지 않는다. 미성숙·비공개·범위 불일치는 보류한다. 사실·가설·행동을 나누고 인과를 단정하지 않는다.

등록은 별도 중앙 occurrence/run/lease/audit 경계에서 직렬 수행한다. 최신 정책의 허용 저장소, 전체 페이지 이슈·최근 종료·관련 PR·현재 기본 브랜치, 재고·중복·표본·수정 후 관찰을 매 생성 직전 검사한다. 코드로 해결 가능한 재현/계약 근거만 등록하고 계측 부재는 계측 후보, 권한·법무·가격·배포 승인은 운영 과제로 남긴다. 응답 유실은 조회 후 판단하며 가짜 이슈는 만들지 않는다. 등록됨·기존 연결·근거 부족·관찰 중·정책 제외를 표시한다.

L3 개발 환경 전체 회귀, 화면 독립 검수 3회, web·service 운영 공개. 1회 수치·그림·근거, 2회 작은 화면·큰 글자·키보드·오류, 3회 수집→발행→정정→이슈 전체 흐름과 회귀. 구현자는 독립 실행으로 가장하지 않는다. 요구사항 실패 테스트를 먼저 쓰며 실제 공급자 연결·화면·운영 검수는 실행 증거를 남긴다. 연결 불가 항목과 미실행은 통과로 표시하지 않는다.

## 2026-10-18 검토 후 승인된 설계 보완

사용자는 2차 리뷰에서 재현된 문제에 대해 공급자 PR #496과 등록 PR #498 모두 **설계를 보완하고 추가 코드 리뷰 없이 회귀·독립 검증으로 마무리**하도록 승인했다. L3 개발 환경 전체 회귀·독립 화면 검수 3회·web/service 운영 공개 범위는 유지한다. 최초 실패와 이미 확인한 해소 근거를 보존한다.

- 시계열·정정·CSV는 의미 세그먼트까지 같은 식별자를 사용한다. 최신 잠정값은 표시하되 판단·요일 비교·이슈 근거는 마지막 유효한 분석 가능 날짜를 명시해 사용한다.
- Apple 재수집 완료는 실행 전체 성공이나 설정 revision과 분리한 인스턴스 URI/버전/성공 범위로 기록한다. 다른 인스턴스 실패나 설정 변경 뒤에도 성공한 원본을 반복 내려받지 않는다. 부분 수집은 원장에 남기되 작업 전체 재시작을 유발하지 않는다.
- Play는 URI별 최대 generation을 실행과 무관하게 보존하고 같은 순서로 최신 partition을 선택한다. 수동 파일의 공급자 버전은 공식 메타데이터 검증 없이 자동 수집의 기준값을 높이지 못한다. 지연과 실제 누락, 분모 0, 비용 snapshot 시각을 구분한다.
- 기존 Play identity의 Android vitals 읽기 권한과 공식 앱 매칭을 확인했다. 공급자의 LA 달력·최신 확보 기간·개인정보 보호를 유지한다. 빈 응답은 0이 아니며, 반올림된 표본·공급자 비율에서 정확한 영향 사용자 수를 역산하거나 비율을 합산하지 않는다.
- 등록의 고객 문제 식별자·후보 내 중복 판단과 POST 시도/최종 결과 기록의 역할을 분리한다. 한 실행의 같은 문제는 다시 시도하지 않으며 linked 결과가 실제 생성 결과를 덮지 못한다. 열린 문제·수정 완료·기각된 문제를 구분하고 마커 없는 운영 과제는 앱별 최신 실행 안에서 보존한다.
- 이미 확인된 PAUSED 차단, 시간·토큰 예산, 생성 POST 거절과 후속 조회 실패 구분, 응답 불명 guard와 읽기 복구, 비민감 logical ID 보존·빈 설정 저장 차단을 회귀에서 유지한다.

추가 코드 리뷰를 요청하지 않는다. 재현된 경계·중복·정정·재수집·결과 유실 시나리오를 실패 테스트와 격리 DB에 고정하고 독립 실행으로 확인한 뒤 최종 통합 후보에서 UI2·UI3·전체 회귀·중앙 배포 검증을 수행한다.
