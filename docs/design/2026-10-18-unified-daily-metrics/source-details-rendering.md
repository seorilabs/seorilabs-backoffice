# 앱별 수집 현황표 초기화 오류 수정

승인된 통합 보고 화면의 오류를 수정한다. 기존 테스트 계획의 L3 개발 환경 전체 회귀, web과 service 운영 공개 범위를 유지한다. 데이터 계약과 표의 표시 내용은 유지하고 닫힌 본문을 그리는 시점을 조정한다.

## 확인한 실패

최종 main `0ccf832`의 실제 운영 보고서에서 초기 로딩 중 React #418이 반복됐다. 숫자와 CSV는 발행 버전과 같았다. 브라우저의 예외 직전 상태에서는 수집 현황표의 `tbody`를 초기화하려는 순간 DOM 커서가 해당 본문의 첫 `tr`에 진입해 있었다. 문서는 아직 읽는 중이었다. 원래 HTML의 기본 태그 중첩 검사에서는 오류가 없었다.

격리된 실제 보고 자료의 개발 모드 5회와 배포용 모드 5회는 미재현이었다. 배포용 모드의 JavaScript 캐시는 확인했다. 해당 결과를 운영 실패의 해결 근거로 쓰지 않는다. React 저장소의 유사한 스트리밍 문제는 원인 후보이며, 우리 사례의 상위 원인으로 확정하지 않았다.

## 표시 구조

서버는 기존 `coverageSummary`로 앱별 확보 범위를 계산한다. 발행본의 원천 행과 함께 작은 `SourceCoverageDetails` 컴포넌트에 전달한다. 처음에는 앱 이름과 확보 범위를 표시하고, 사용자가 펼치면 같은 고정 행으로 표를 그린다. 접었다가 다시 펼쳐도 자료를 다시 수집하거나 조회하지 않는다.

스크립트가 도착하기 전에 사용자가 네이티브 `details`를 연 경우에는 초기화 후 실제 열림 상태를 읽어 본문을 표시한다. 클릭, Enter와 Space의 기본 동작을 유지한다. 기존 표의 상태, 기준일, 원인과 해결 방법, 실행 ID를 그대로 표시한다. CSV와 보고서 문서, 원천 및 알림 저장 경로는 기존 서비스를 따른다.

## 검증과 운영 확인

- 실패부터 기록한다. 실제 운영 예외와 별도로 닫힌 표가 본문 행을 먼저 만들지 않는 회귀 테스트를 추가한다.
- 최종 후보에서 전체 test, typecheck, lint, 웹과 worker 빌드, migration 안전 검사와 중앙 검증기를 실행한다.
- 독립 실행자는 실제 고정 보고 자료로 초기 닫힘, 클릭과 키보드, 재펼침, 누락과 확인된 0, 버전 선택 및 CSV와 DB 보존을 검증한다. 실제 자료에 없는 확인된 0은 별도 격리 자료로 구분한다.
- 기존 화면 검수 1~3회와 실패 원본을 보존한다. 이번에는 같은 화면의 기능 수정에 대한 추가 회귀를 기록한다.
- 정확한 SHA와 이미지로 배포한 뒤 캐시된 브라우저에서 과거 및 현재 보고서와 표 확장을 읽는다. 실제 디스코드 카드와 수치, 링크의 고정 버전도 확인한다. 표시 변경 때문에 새 보고서 버전을 만들지 않는다.
