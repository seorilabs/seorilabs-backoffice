## 변경

회차 설정과 작업 목록을 고정하는 `KeywordCollectionBatch`, 추가 전용 `KeywordObservation`을 추가했다. 같은 회차와 행의 해시가 재시도 중복을 막는다. Apple 일별 기록은 마지막 성공 관측만 갱신하며 기존 기록을 소급 생성하지 않는다.

검색어 수집은 평점, 지원 링크, 경쟁 앱과 공지 수집에서 분리했다. 수집은 07:20, 13:20, 20:20 KST이며 보고는 08:40, 14:40, 21:40 KST다. 회차는 65분 내 완료하며 남은 예산이 부족한 검색어는 미수집으로 기록한다. Apple은 3.5초, Play는 5초의 요청 간격과 응답 크기, 제한 시간, 재시도 상한을 유지한다.

보고는 현재 완료 회차의 성공 관측만 사용한다. 마켓, 출처, 국가, 언어와 검색어별 이전 성공값을 비교한다. 큰 변화 최대 2개와 최근 7일 덜 소개한 검색어로 최대 3개를 구성하고 브랜드는 최대 1개다. 이미 소개한 같은 결과는 반복하지 않는다. 같은 보고 회차의 재실행은 기존 이벤트와 전송 이력을 유지한다.

일별 그래프는 기존 구조를 유지하고 선택적인 `market=google-play` 조건을 추가했다. 표와 CSV는 마켓, 출처와 반환 개수를 표시한다. 성공 뒤 수집 실패가 있어도 성공 순위를 지우지 않으며 최근 시도 상태를 함께 표시한다.

검색어 보완 도구는 기존 중앙 API의 설정 생성과 활성화 서비스를 사용한다. 공개 확인, 기존 초안, 설정 버전과 멱등성을 검사하며 기존 국가와 검색어, 다른 설정을 보존한다. 후보는 운영 정본이 아니다.

## 개발 검증

- AC-1, AC-2, AC-5: 격리 MySQL 9.2에서 하루 세 회차, 재시도 불변성, 마지막 성공값, 마켓 분리와 같은 보고 회차 중복 방지를 실행했다. 외부 전송은 실행하지 않았다.
- AC-3: 큰 변화 2개, 총 3개, 다른 앱 우선, 브랜드 1개, 7일 반복 억제와 짧은 반환 범위의 잘못된 등락 방지를 검사했다.
- AC-4: Play 공개 원문은 일반 검색 `farm tycoon` 30개, 브랜드 `Bloomhand` 50개, 임의 빈 검색 0개였다. 본문 앱 링크 순서를 대조했다. 광고와 추천, 중복, 잘린 응답, 차단과 구조 변경은 합성 입력도 검사했다. 실제 광고 포함 원문 대조는 아직 완료하지 못해 **Play 운영 활성화는 보류한다**. `KEYWORD_PLAY_ENABLED=false`를 유지한다. 실제 국가 적용이나 기기 순위 일치를 검증했다고 기록하지 않는다.
- AC-6: 공개 미확인, 기존 초안 충돌, 기존 국가와 검색어 보존, 30개 상한과 원본 불변성을 검사했다. 운영 설정 변경 결과는 배포 후 별도로 기록한다.
- AC-7: 격리 Next.js 실행 화면에서 375px, Apple과 Play 전환, 검색어 체크박스 키보드 조작, 날짜 Enter 적용과 표 출처를 확인했다. 화면 밖 넘침과 브라우저 실행 오류는 없었다.
- AC-8 개발 부분: 관련 테스트, 전체 단위 테스트와 Python 테스트, typecheck, lint, 더미 DB build, worker 번들, migration 안전 검사와 MySQL schema 대조를 실행한다. lint의 기존 `release-tag-ledger.test.ts` 미사용 변수 경고는 변경 범위 밖이다. 최종 후보 SHA의 실행 결과와 중앙 검증은 저장소 밖 근거 JSON에 결합한다.

## 운영 반영과 남은 확인

중앙 before-deploy 검증 뒤 웹, worker와 관련 CronJob에 같은 이미지 digest를 적용하고 source SHA, 일정과 활성 상태를 재조회한다. 기존 하루 1회 market 작업과 주간 작업은 유지한다. 운영 채널에는 수동 테스트 메시지를 보내지 않는다.

배포 뒤 자연 수집, 회차별 선정과 Discord 실제 수신은 각각 따로 확인해야 한다. 첫 신규 수집 일정 이전의 보고는 현재 회차 자료가 없으면 생략한다. 자연 실행을 수동 실행으로 대체하거나 성공으로 표시하지 않는다.

복구는 적용 전 조회한 이미지와 기존 하루 1회 일정으로 되돌리며 새 관측, 일별 이력과 설정 버전은 보존한다. 설정 복구도 기존 서비스를 통한 새 버전으로 한다. 검수 원문과 화면은 NAS1dual의 `agent-artifacts/seorilabs-backoffice/2026-10-28/<후보 SHA>/keyword-observations`에 복사와 해시 대조 후 이관한다. 최종 실제 위치와 배포 결과는 실행 이슈에 기록한다.
