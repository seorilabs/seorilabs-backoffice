# Discord 보고 개편 전체 검수 계획 변경

2026-10-18 사용자 답변: **전체 범위 3회로 계획 수정 후 계속 (권장)**. 승인 수신 확인은 2026-10-17T15:07:31Z 이전이다. 원래 구현·출시 범위는 [기존 설계](../2026-10-17-discord-human-reports/design.md)와 동일하다. 이번 승인은 기존 집중 검수의 범위 누락을 소급 통과시키지 않고, 핵심 기능 전체를 확인하는 새 검수 3회를 실행하는 승인이다. 기기·운영 데이터는 사용하지 않는다. 약 20–30분 추가를 제시했고 누적 총 5회 한도를 승인받았다.

## 원본 이력과 새 실행의 연결

| 누적 실제 실행 | 구분 | 상태·용도 |
| --- | --- | --- |
| 1 | 기존 판단 품질 R1 | 원래 명칭·계획·실패 원문 보존. 핵심 기능 전체 범위 미충족. |
| 2 | 기존 보고서 품질 R2 | 원래 명칭·계획·실패 원문 보존. 핵심 기능 전체 범위 미충족. |
| 3 | 새 전체 검수 1회 | 핵심 11개 기능·사용성 전체, 판단 품질과 인수조건, 기존 결함 재현·수정 확인. |
| 4 | 새 전체 검수 2회 | 핵심 11개 기능·사용성 전체 재실행, 오류·취소·복구·좁은 화면·큰 글자·키보드. |
| 5 | 새 전체 검수 3회 | 핵심 11개 기능·사용성 전체 및 44개 기능 회귀, 재시작·저장 복구·전체 작업 연결. |

중앙 검수 근거의 `reviewRounds` 1/2/3은 위 **새 전체 검수**의 순번이다. 실행 기록에 누적 3/4/5를 함께 적는다. 기존 두 회차를 처음부터 예비 검수였다고 바꾸지 않는다. 원본 보고서·발견 결함·중앙 `FEATURE_COVERAGE functional/ux 1/2`와 `THREE_UI_ROUNDS_REQUIRED` 차단 로그를 연결해 보존한다. 총 실행 수를 숨기거나 과거 실행을 새 계획에 소급 편입하지 않는다.

## 매 회차 범위

기능 목록 `docs/qa/feature-inventory.json`의 핵심 11개: 탐색·리디렉션, 앱 목록·작업공간, 조직 보고, 앱·마켓 지표, 작업 개요, 피드백·시장, 수집 상태 화면, 인사이트·근거·초안, 로컬 초안 편집, 자동화 현황, 검색 순위·그래프.

각 회차 전에 최종 후보 SHA, 기능·사용성 기대 결과, 순서, 페르소나, 격리 데이터·저장 경로·증거·판정을 검수자가 기록한다. 실제 웹 입력·이동·저장된 초안 복원·오류·취소·상태 표시를 확인한다. 결제·GitHub·마켓 같은 provider의 실제 실행은 로컬 대체 입력·명시적 권한 거부·계약 실행과 구분한다. 화면 조회나 단위 테스트만으로 실제 provider 성공을 주장하지 않는다.

변경된 보고 흐름은 실제 격리 MySQL·서명된 이벤트 수신·워커·Discord HTTP 캡처로 검증한다. 숫자·본문·PNG·웹·CSV는 실제 공개 순위 snapshot과 합성 경계 자료를 대조한다. 기존 R1 중복 PATCH와 R2 상태 라벨 겹침은 새 1회차부터 재확인한다.

## 정지·완료

새 3회차 뒤 미검수나 주요 결함이 남으면 누적 6회는 별도 승인 없이 시작하지 않는다. 최종 같은 후보의 전체 회귀·typecheck·lint·build·migration·중앙 검증기가 통과한 뒤 Ready PR·병합·Backoffice 운영 배포·유용한 실제 Discord 보고 확인까지 기존 승인을 이어간다. 개별 앱 마켓 배포는 하지 않는다.
