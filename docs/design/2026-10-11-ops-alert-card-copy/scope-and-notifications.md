## 앱·키워드 범위가 보이는 화면

기존 `/feedback` 상단에 “검색 순위 모니터링” 조회 영역을 둔다. 활성 추적 앱 수와 예정 조합 수, 최신 수집 성공/실패/미수집 조합 수를 분리한다. 각 앱의 국가·검색어·최근 수집 시각·수집 상태·설정 링크를 한 목록에서 확인한다. 전날 기준 자료와 오늘 시도를 섞어서 현재 성공 건수로 표현하지 않는다.

화면 상태: 추적 중 / 검색어 미설정 / 공개 리스팅 미확인 / 일시중지 / 수집 실패 / 미수집. “설정됨”과 “실제로 수집됨”은 다르게 표시한다. 특정 국가 리스팅 없음과 해당 검색어 결과 목록에서 앱이 나타나지 않음을 구분한다.

기존 `FeedbackView`의 최신 100개 관측 목록은 전체 설정 범위가 아니다. 새 영역은 중앙 ACTIVE ConfigRevision과 수집 원장의 동일 조회 경계를 재사용하며, 새 설정 저장소나 병렬 수집기를 만들지 않는다. 소형 화면은 앱별 줄바꿈 또는 목록 내부 스크롤을 사용하고 페이지 전체 가로 넘침을 만들지 않는다. 설정 변경에는 기존 중앙 validator·RBAC·동시성·감사를 그대로 사용한다.

## 멘션이 붙는 현재 원인

`src/lib/notifications/deploy.ts`의 일반 전송 경로는 `destinationKey === DISCORD_OPS_ALERTS`일 때마다 `release_ops` 역할을 전달한다. 신호의 중요도나 사용자 피해를 확인하지 않는다. 수집 신호의 기본 중요도는 `info`인데 `source-stale`·`source-recovery`라는 종류만으로 ops-alerts에 라우팅되므로 멘션이 붙는다. 실제 incident 경로 역시 현재 OPEN이면 severity와 무관하게 역할을 넣는다.

| 사건 | 메시지 | 멘션 |

채널 이름·본문 문자열·embed 색상만으로 멘션을 허용하지 않는다. 기본값은 멘션 없음이다. 신뢰된 내부 incident의 실제 중요도·상태와 최초 전송 여부를 사용한다. 일반 OPS_ALERT 및 이미 대기 중인 이전 형식의 수집 payload도 이 규칙을 적용해 과거 카드가 다시 호출하는 것을 막는다. 미등록 일반 알림은 조용히 전송하고 진단 가능하게 남긴다. 실제 critical 장애의 최초 알림은 유지한다. 외부 입력에 임의 멘션 권한을 추가하지 않는다.

Play 실패 구간은 같은 앱·소스·대상에서 마지막 정상 완료 뒤의 실패·부분 수집을 묶는다. 정상 `observed / empty` 완료가 구간을 닫는다. 60분 경계는 실제 수집 원장의 시각으로 판단하고, 자료가 없으면 지속 시간이나 권한 상실을 추측하지 않는다. 하루가 바뀌거나 failed→partial 상태가 달라져도 같은 실패 구간을 새 경고로 만들지 않는다. 미확인·실행 중·중복·동시 수집 결과는 정상 회복으로 판정하지 않는다.

일반적인 15:15 실패→15:30 부분 수집→15:45 회복은 새 정책에서 **개별 카드·멘션 없이 정기 요약에 남는다**. v1의 실패·회복 카드 디자인은 장시간 지속 실패와 그 회복에 사용한다. 수집 실패를 실제 앱 장애·심사 거절·공개 취소로 승격하지 않는다.

## 구조·적용·검증

v1 코드 범위에 다음을 추가한다.

- `src/lib/insights/queries.ts`, `FeedbackView.tsx`: 중앙 설정 범위와 실제 수집 범위를 보여 주는 조회·표시.

- 중앙 control-plane 서비스: 위 표의 승인된 키워드만 새 ConfigRevision으로 추가하고 활성화. DB 직접 수정 금지. 적용 직전에 최신 revision·현재 설정을 다시 읽어 사용자의 새 변경을 보존한다.

복구는 기존 이미지와 직전 중앙 revision을 서비스로 재활성화하며 수집·분석·감사 기록을 삭제하지 않는다. 이미 발송한 알림의 취소나 반복 전송을 복구로 간주하지 않는다.

## 승인·추적

사용자의 “확대안도 적용하고”로 **앱·키워드 범위 화면, 12개 앱·111조합 설정 확대, 일시 실패 요약·60분 경고·중요 장애 최초 호출 규칙**이 승인됐다. 중앙 설정은 새 revision을 활성화하고 12개·111조합 및 다른 설정 보존을 확인했다. 코드 구현·검증·병합과 운영 배포·실제 Discord 전송 확인은 [검증 기록](validation.md)에서 구분한다.
