# 달빛 맞고 운영 조회 개발 검증

새 조회는 첫 판 완료율과 두 번째 판 시작률을 순서가 있는 사건으로 계산하고 실제 내보내기 관찰일에서만 D1과 D7을 낸다. 분석을 허용한 신규 저장만 포함하므로 전체 마켓 설치의 지표가 아니다.

- 개발 검사: 신규 5개를 포함한 TypeScript 2,007개와 Python 15개 통과. typecheck와 build 통과. lint는 오류 0개, 기존 `release-tag-ledger.test.ts`의 미사용 변수 경고 1개다.
- SQL: 날짜를 DATE 리터럴로 바꾼 실제 생성 문자열이 `seorilabs/matgo`의 `analytics/cohorts.sql`과 바이트 단위로 같음을 비교했다. 이 SQL의 합성 행 BigQuery 실행 근거는 Matgo `docs/qa/analytics-sql-independent-29dfcf2.json`이다. 신규 운영 데이터 조회나 SDK 수신을 증명하지 않는다.
- 실제 HTTP: 격리된 로컬 production 서버에서 토큰 없음 401, 잘못된 일수 400, 연결 실패 503과 `unavailable`을 확인했다. 테스트 DB는 연결할 수 없는 로컬 더미이며 운영 DB, 설정과 원시 행은 읽거나 바꾸지 않았다.
- 테스트 우선: 새 진입점이 없어 import가 실패한 초기 로그와 Prisma 생성 전 환경 실패는 기능 실패로 세지 않는다. 신규 조회에는 독립된 이전 실행 경로가 없어 기존 SQL의 실제 합성 실행과 반환 상태, null 보존, 식별자와 날짜 거부 검사로 대체했다.

실제 데이터셋과 원시 행이 아직 없으므로 중앙 GA4 연결은 미활성이다. 배포와 운영 API 조회는 이 개발 실행과 별도 기록한다. 7일과 14일은 조회 창 길이이고 D7 값은 관찰일이 실제 존재하는 코호트에서만 나온다.
