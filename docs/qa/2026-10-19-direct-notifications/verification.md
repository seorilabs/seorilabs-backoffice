# 건별 알림과 리뷰 통계 검증

사용자 지시와 두 선택(Platform 사용자 ID, 11시 전날 통계)을 설계에 고정했다. Backoffice #520과 Platform #238이 수신자 우선 배포로 연결된다.

- 변경 전 실제 보고 정책과 이벤트 파서에서 새 리뷰 건별 발송과 승인 UID가 거부되는 요구사항 실패 2개를 확인했다. [원본](tdd-red.txt).
- 신규 일간 통계 모듈에는 기존 실행 진입점이 없어 가져오기 오류를 요구사항 실패로 세지 않았다. 중복 수정, 마지막 별점, 마켓 분리, 평균과 분포 일치, KST 11시 경계, 빈 표본, 같은 키와 정정, 잘못된 날짜를 격리 fixture로 검증했다.
- 실제 POST와 원장 및 outbox 서비스를 실행하는 격리 DB 경계에서 계정과 버전, 미등록 앱, 중복, enqueue 실패 후 재전송, 광고와 테스트 결제의 전용 채널을 검증했다. 새 UID와 금지 속성, 서명 및 보고 중지도 검사했다.
- 초기 관련 23개 검사와 전체 단위 1,914개가 통과했다. 새 표시와 충돌하는 예전 문자열 예상값 4개는 실패를 보존하고 승인한 새 표시에 맞춰 수정했다. lint는 기존 release-tag-ledger 테스트 경고 1개다. 최종 SHA의 실행, build와 중앙 근거는 별도 보관 자산과 PR에서 연결한다.
- 첫 계정 및 첫 지급만 별도 카드로 보내던 생산자는 새 건별 경로로 대체해 제거했다. `operational_milestone` 스키마와 과거 기록은 보존한다. 지급이나 결제 원장을 수정하지 않았다.

운영에서는 실제 원장의 최근 미발송 이벤트와 보존 중인 블룸핸드 리뷰를 확인용으로 사용한다. 동일 키가 SENT이면 다시 보내지 않고, 이미 제외된 원문은 기존 outbox 서비스로만 재개한다. 원문과 UID를 검수 로그에 복제하지 않는다. 일간 통계는 명시한 날짜와 앱의 첫 발행을 수동으로 확인할 수 있으며 자동 11시 발행도 같은 키를 사용한다. 가짜 운영 이벤트를 만들지 않는다. 실제 발송과 provider 본문 확인 전에는 운영 성공으로 기록하지 않는다.
