실제 Codex CLI에서 격리 worktree의 한 파일 생성과 Git commit, 기존 magicsih GitHub 계정의 읽기 인증을 확인했다. 승인 전 분석은 read-only이며 승인 실행은 기존 사용자 CLI sandbox 설정을 재사용한다. 전역 설정과 계정은 바꾸지 않았다. 공통 폴더 관측과 개별 문서 문제를 같은 ID로 강제해 후속 집필 제안이 막히는 경우를 실제 MySQL에서 먼저 실패로 확인하고, 로컬 상태 관측만 여러 안정된 문제 키의 근거가 될 수 있게 수정했다. GitHub와 provider 근거는 기존 문제 키 일치를 유지한다. 원격 객체 관측은 fetch만 하고 원본 checkout과 사용자 변경을 보존한다.

최종 요구사항 대조에서 디스크 여유 공간이 로컬 관측에 없는 경우와 원격 기본 브랜치가 바뀌었는데 기존 remote-tracking HEAD에서 설계를 만드는 경우를 실패 테스트로 재현했다. 등록된 실제 PC 경로의 전송 없는 사전 점검에서는 첫 커밋이 없는 집필 저장소가 관측을 중단시켰다. 원고나 checkout은 바꾸지 않았다.

로컬 관측은 디스크 전체와 남은 bytes를 기록하고, 정상적인 첫 커밋 전 Git 상태를 별도로 다룬다. 설계의 기준 커밋은 원격 HEAD와 기본 브랜치를 직접 읽고 필요한 객체를 fetch한 뒤 고정한다. 실제 파일을 고치지 않고 원격 기본 브랜치만 변경하는 격리 Git 회귀와 빈 집필 저장소, 디스크 수치 회귀를 추가했으며 실행기 Python 15건이 통과했다. 분석 지침에는 승인 계획의 미완료와 집필, 출판 자료의 불일치 대조를 명시했다.

기존 공식 화면 검수의 후보는 `40fe10c`와 `a85a2b5`로 보존한다. 위 실행기 변경 이후 후보에 그 결과를 소급하지 않는다. 추가 회차의 사람 승인과 메타데이터 누락 없는 과거 검수 기록을 보존할 중앙 형식 지원을 검토한 뒤 build와 배포 검증을 이어가야 한다. 검수 도구의 시간 초과, 초기화 대기 오류와 실제 제품 결함도 구분해 원본을 남긴다.
