## 테스트 우선 검증

- 최초 대역 연결 시 Node mock이 Prisma proxy 메서드를 찾지 못한 실행은 환경 실패이며 요구사항 실패로 세지 않았다. 원본은 로컬 작업 기록에 보존했다.
- DB singleton을 파일별 격리 객체로 연결한 뒤 실제 POST, 서명 검증, 기존 마일스톤, 기존 outbox를 실행했다. 변경 전 6개 중 3개가 요구사항 때문에 실패했다. [원본](tdd-red.txt): 계정 알림 없음, 미등록 앱 알림 없음, enqueue 경로가 없어 실패 후 재전송 검사도 실패.
- 복원 뒤 관련 35개 검사 통과: 6개 실제 라우트 흐름, 기존 서명·속성·한 줄 표시, 중복 응답, 최초 카드, 보고 선정·중지와 outbox 계약.
- 최초 typecheck는 테스트 fixture 배열의 추론된 undefined 속성으로 실패했다. 배열을 OperationalEventInput[]로 명시해 검사한다. 제품 실행 실패와 구분한다.

최종 후보 SHA에서 서비스 실행과 typecheck, lint, build를 다시 실행하고 외부 근거 자산과 PR에 결과를 기록한다. 초기 통과를 다른 SHA의 최종 통과로 옮겨 적지 않는다. 새 화면, 기기, 마켓 출시는 범위 밖이다.

## 적용 계획과 남은 상태

검증한 immutable 이미지의 웹 Deployment만 갱신한다. 스키마, 워커와 정기 실행은 변경되지 않는다. 전체 배포의 reconcile 충돌 #517은 미해결이며 이번 웹 반영으로 해결됐다고 기록하지 않는다. 실제 새 이벤트 또는 기존 원장의 최근 미발송 한 건을 기존 수신 API로 재처리하고 Discord 공식 API에서 본문과 실제 메시지 ID를 확인한다. 같은 이벤트 재처리 뒤 메시지 수가 늘지 않는지도 대조한다. 적용과 live 확인 전에는 완료로 기록하지 않는다.
